# Avery 61528 laser sheets

This fork adds Avery 61528 to upstream QR Code Label 1.5.0, identified as version
1.5.1 in GLPI. It uses 14 labels per US Letter sheet: 2 columns by 7 rows,
69.85 x 31.75 mm each. The PDF positioning follows the actual cut paths in Avery's
official U-1264-01 PDF (the same downloadable template is used for 61528 and 94284).

Sources:
- https://www.avery.com/templates/presta-61528
- https://www.avery.com/templates/presta-94284

## Upgrade an existing installation

1. Back up the existing `qrcodelabel` plugin directory, plugin configuration/logo
   and the GLPI database. Note whether it lives under `marketplace/` or `plugins/`.
2. Disable the plugin in GLPI. **Do not uninstall it**: uninstalling deletes its tables.
3. Download this fork's `avery-61528` branch as a ZIP. Extract it, rename the
   extracted plugin directory to `qrcodelabel`, and replace the old code in the
   same location. Do not leave a second copy under another plugin directory.
   On Docker, update the host volume or image that provides the plugin so a
   container recreation does not restore the old version.
4. Preserve the installation's existing file ownership/permissions. Run the
   plugin update in GLPI if offered, then enable it. The upgrade adds the
   `Avery 61528` profile without changing your previous default.
5. If the profile is missing, open Tools > QR Code Label and add a print profile:
   name `Avery 61528`, label format `Avery 61528 (14 / Letter)`, Black & White,
   date off, Letter, Portrait. Set it as default if desired.
6. Use Owner text for the school/company name, for example `Property of TCA`.
   Existing label content is retained (asset name, type, serial and optional
   date/location/owner/inventory number). This change does not add a model field.

No new database columns are needed. Existing tape profiles continue to work.
The Avery profile always produces a Letter portrait PDF, including when the
global output format is PNG or Both. It does not produce a tape PNG.

## Label layout

The logo and all asset information occupy the right side. The left side is
reserved for a 29.75 mm square QR image, with a 1 mm outside margin and the
encoder's four-module quiet zone. The logo retains its aspect ratio and never
reduces the QR size. This layout applies only to Avery 61528 PDF output.

## Print

Select assets > Actions > QR Code Label - Print QR labels, or open an asset's
QR Label tab. Choose Avery 61528 and the desired number of copies per asset.

- First label position: 1 to 14, read left to right, then down (1 = top left,
  2 = top right, 3 = second row left). Skipping applies only to the first page;
  additional pages begin at position 1.
- Horizontal/vertical adjustment: optional, -5 to +5 mm, default 0. Positive
  values move right/down. These settings affect Avery only and apply to every
  page. Test before reusing partially occupied sheets, following printer guidance.
- Print the downloaded PDF with Letter paper, portrait, **Actual size / 100%**,
  single-sided, with scaling/fit-to-page disabled. Choose the printer's label
  media setting if applicable.

First print on plain paper and hold it over an unused label sheet against a
light. Check the first and last rows and both columns before using label stock.
If the whole image needs moving, adjust the offsets. Progressive drift usually
indicates scaling or the wrong paper size, rather than a constant offset.

## Validation

Standalone checks (PHP with GD and mbstring, TCPDF, Python with pdfplumber):

```sh
php tests/sheet-layout.php
php tests/render-sheet.php > /tmp/label-test-results.json
python3 tests/check-pdfs.py /tmp/label-test-results.json
```

Set `TCPDF_PATH` if TCPDF is not installed at `/usr/share/php/tcpdf/tcpdf.php`.
The rendering test uses sample data and GLPI stubs, not a live GLPI instance.
It checks actual PDFs, pagination, a partially used sheet, calibration, forced
PDF output and the existing Brother/A4 layout. Live GLPI upgrade, form submission
and physical printer alignment must still be verified on the installation.

To roll back, disable this version, restore the backed-up 1.5.0 directory, and
re-enable it. Select an original tape profile; the old version cannot render
the Avery profile.

## GLPI 12 compatibility

The version range now includes GLPI 12 (maximum exclusive: 13.0.0). The
`CSRF_COMPLIANT` hook is registered only when present, since GLPI 12 removed
that declaration; core CSRF protection is not disabled. Version remains 1.5.1.
Bootstrap checks use the real Hooks classes from GLPI 11.0.0 and 12.0.1.
Standalone PDF checks do not replace activation, form submission and download
testing in the live GLPI 12 instance, particularly with its bundled TCPDF 7.
